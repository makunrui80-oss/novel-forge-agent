小说智能体 · 使用说明
=====================

一、启动
1. macOS 双击「启动.command」；Windows 双击「启动.bat」；Linux 运行「启动.sh」。三套入口都会调用同一个跨平台启动器「启动.py」。
2. 第一次会自动安装运行环境，等 1-2 分钟，不要关窗口。
3. 看到终端里打印「小说智能体已启动」和地址后，浏览器会自动打开。
   如果没打开，手动打开浏览器，输入终端打印的地址（端口被占用时可能是 8766 或其他端口）。

二、重要
- 启动器会把服务与启动窗口脱离，终端窗口关闭后服务仍会继续运行；再次双击入口只会打开已有服务，不会重复启动。
- 停止使用：在终端窗口按 Ctrl+C，或直接关掉窗口。

三、双击没反应 / 打不开怎么办
1. 在「启动.command」上点右键 → 打开 → 再点「打开」。
   （macOS 第一次运行本地脚本会拦截，这是正常现象）
2. 还是不行，双击「诊断.command」，把窗口里的内容截图发我。
3. 也可以看同目录下的「启动日志.txt」，最后几行通常就是原因。

四、第一次使用
1. 打开网页后，先点左侧「08 设置」。
2. 点「添加供应商」，协议只选两种：OpenAI 兼容（DeepSeek/通义/Kimi/豆包/中转都选这个）或 Anthropic。
   地址、Key、模型名都自己填，模型名用逗号分隔。
3. 点「测试接通」，会用模型列表里的第一个模型试一条；成功后再点「保存全部设置」。
4. 在「分环节模型」里给五个环节选模型，保存。
5. 回到「总览」，点「新建」，上传你要学习的**参考书**（别人写的高分小说，不是你自己的稿）。
6. 点「继续下一批」开始拆书；有了可用细纲即可点「本批结束后转大纲」，在「原创大纲」里填新书要求，生成另一本新书，不必拆完整本。
7. 大纲生成后，到「创作宪法」确认并锁定，再去「正文写作」点「继续下一批」或「自动写完」。正文按新书大纲和承接卡推进，不依赖剩余参考书章节。
   每章动笔前自动重新读取完整原创大纲、紧邻前五章的完整正文，并保留开篇前五章作为长期主题记忆。已润色的章节优先读取润色正文；更早的开篇长章节使用首、中、尾节选，重叠章节不重复发送。开篇不足五章时只读此前已写章节，不编造后续剧情；缺少应有的开篇正文或大纲时，会提示补齐后再写。批量、续写和重试都执行同一规则，无需开启设置。
   如果已有大纲却显示没有章节计划，到「原创大纲」点「补提取章节计划」即可；直接开始正文也会自动整理。无需重新拆书，原大纲会备份，已锁定的宪法会保留。大纲只输出了部分章节也可以先写这些章节。
   界面会一直显示：参考书《X》 → 新书《Y》，不要搞混。

五、模型返回空内容怎么办
- 程序会自动要求接口返回非流式完整答案，并对空回复、截断和非 JSON 自动重试。
- 如果任务仍失败，先在「任务中心」查看具体错误，再点「继续」；不要连续重复点击同一个按钮。
- 同一项目的拆书严格逐批执行：上一批完成并落库后才开始下一批；不同项目可以并行。想降低不同项目之间的任务并发，可设置 `NOVEL_TASK_WORKERS=1`（默认 2，最高 4）。
- 上传后拆书页会先显示章节识别、短章和自动分块提醒；开始前建议抽查章节标题和前几章内容。
- 每批细纲会检查章节是否漏掉、摘要是否为空；连续失败会保留原始回复和错误状态，不会误标完成。
- 点「继续」时，已有完整细纲会复用，失败批次只补做缺失工作；每批细纲完成后再更新全书档案。
- 拆书质量报告会显示章节覆盖率、编号不一致提示和真正需要重试的批次；编号对不上不会阻塞拆书。

六、常见问题
- 朱雀自动检测：在「08 设置 → 朱雀检测」选择「腾讯云官方 · Makers 朱雀」，填写 Makers → Models → API Key 页面创建的密钥，点「测试检测」，成功后启用并保存。官方调用地址已内置，只需填密钥，不必另建企业网关。
- 不要使用 detector.example.com 之类的示例地址。检测连接失败不会删除正文，配置修好后可对已有章节重新全检。
- 网页显示「连接被拒绝」：终端窗口是不是关了？重新双击启动。
- 提示端口被占用：程序会自动换一个端口，看终端里显示的地址。
- 余额：设置里填当前余额和阈值（默认 3 元），填了模型价格后会自动扣减。
- 数据都在 data/novel.db，备份整个文件夹即可。
- 如果写作页显示“几条偏离”，展开对应批次即可看到具体是第几章、正文证据和拉回建议。点击“重新承接并定位偏离”会重新核对该批并把纠偏动作传给下一批，不会自动覆盖已有正文。

七、朱雀分数与自然编辑
- 朱雀官方返回的 `ratio_confidence` 是 0–1 的疑似 AI 内容占比，程序按比例显示为 0–100 分；返回 1.0 时显示 100.0，这是接口结果，不是程序把分数写死。
- 超过合格线后，程序最多按设置进行有限次自然编辑，编辑提示会要求打散句式、区分人物口吻、减少套话、让动作和感官细节服务于情节。编辑不会改动章节主线，也不会在正文中写“AI 检测”等说明。
- 任何检测器都有误判和模型偏差，无法保证每篇文章都低于某个分数。若连续返回 100，任务中心会提示“检测接口连续返回高分”，正文仍会保留，方便你人工审核或换模型复检。

【2026-10-28 启动与改稿修复】
- Mac 使用项目文件夹内的“启动.command”。文件夹可以改名；桌面入口请制作替身，不要只拖出这一个文件。
- 启动器识别本目录的程序和代码版本。代码更新后，空闲服务会重新启动；有任务时保留运行，任务结束后再双击一次。
- 每章重写、优化和自动编辑同样读取大纲、章节计划、前五章正文，先检查事实与承接再保存。
- 新写发现核心事件或承接问题时，自动修复一次。无法确认可用时保留候选稿和具体原因。
- 自动编辑只有在剧情检查通过、重新检测分数改善后才替换。分数不降或上升时保留较低分原稿。
- 编辑正文后旧检测分数失效；重新检测时会记录正文版本，防止把旧分数当成新稿结果。
- 第三方检测分数不能保证。外部润色 Skill 必须经过真实正文测试，不能用“安装成功”代替降分效果。
